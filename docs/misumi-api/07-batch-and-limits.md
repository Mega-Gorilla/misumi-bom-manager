# 07. バッチ（複数型番同時問い合わせ）と件数・レイテンシ上限

単価・出荷日チェック API（[03](./03-price-delivery-check.md)）が **複数型番の同時問い合わせ（バッチ）に対応するか**、
また **何件まで返るか**を実測した結果。

## 結論

- **バッチは可能。** リクエストボディの `detailList` は配列で、**1 リクエストに複数明細を入れると全件まとめて返る**。
- **件数のハード上限は観測されず**（最大 **1000 件で HTTP 200・欠落ゼロ**）。
- ただし **2000 件で HTTP 504「upstream request timeout」**（約 5 分でゲートウェイがタイムアウト）。
  → **件数ではなく「サーバ処理時間（レイテンシ）」が実質の上限。**
- **実用上の推奨は 1 リクエスト 50 件前後**（応答 3〜5 秒）。大量時はチャンク分割 + 低並列で処理する。

## 実測データ（2026-06-24, 未ログイン, qty=1）

検証方法：Playwright + Edge で `jp.misumi-ec.com` を開き Akamai を通過、
ブラウザの Cookie を引き継いだ HTTP クライアント（Playwright APIRequestContext, CORS 非対象）から
`POST .../sales-price-delivery/check` を件数を変えて送信。
型番は CBT/CBTB/E-GBSCB 系の実型番 111 種を循環使用（1000 件以上は重複でパディング）。

| リクエスト件数 | HTTP | 返却件数 | 所要時間 |
|---:|:---:|---:|---:|
| 1 | 200 | 1 | 0.6 秒 |
| 51 | 200 | 51 | 3.6 秒 |
| 111 | 200 | 111 | 14.0 秒 ※ |
| 150 | 200 | 150 | 9.4 秒 |
| 200 | 200 | 200 | 11.2 秒 |
| 300 | 200 | 300 | 14.4 秒 |
| 500 | 200 | 500 | 14.8 秒 |
| 800 | 200 | 800 | 22.7 秒 |
| 1000 | 200 | 1000 | 42.0 秒 |
| **2000** | **504** | **—** | **~297 秒（upstream request timeout）** |

※ 111 件が 150/200 件より遅いのは初回（コールドスタート）の測定ノイズと推定。中規模帯（100〜500 件）は概ね 10〜15 秒でほぼ横ばい、800 件超で急増する傾向。

## 解釈

- 返却件数は常にリクエスト件数と一致（**重複入力も行ごとにそのまま返る＝サーバ側でデデュープしない**）。
  → `detailList` の各要素は独立した明細として処理され、件数制限は実装上設けられていない（少なくとも 1000 までは）。
- 500 件付近まで応答がほぼ一定なのは、サーバ側である程度並列処理しているため。
  800 件超で急増し、2000 件で約 5 分のゲートウェイタイムアウト（504）に到達。
- したがって**安全に使えるのは「数分以内に返る件数」**であり、UX を考えると遥かに手前で区切るべき。

## 実装ガイドライン（本アプリ向け）

| 用途 | 1 リクエストあたり件数 | 想定応答 | 補足 |
|---|---|---|---|
| 対話的な単発〜小ロット | 1〜50 | 〜5 秒 | 即時表示向け |
| BOM 一括（バックグラウンド） | 100〜200 | 10〜15 秒 | 進捗表示推奨 |
| 大量 BOM | チャンク分割（例 100/件）| 合計に比例 | 並列は 2〜3 まで・行間ウェイト |
| 非推奨 | 1000 以上 | 数十秒〜504 | タイムアウト・サーバ負荷 |

推奨方針：

1. **チャンク化**：BOM が大きい場合は 1 リクエスト ≤ 100 件に分割。
2. **低並列**：同時実行は 2〜3 本まで（[05](./05-akamai-and-auth.md) の礼儀的レート制限）。
3. **タイムアウト**：クライアント側タイムアウトは 60〜90 秒程度に設定し、超過チャンクは縮小して再試行。
4. **キャッシュ**：取得済み単価・出荷日は最終取得日時付きでローカル保存し、再問い合わせを抑制。

> 注意：これらは観測値であり、サーバ構成・負荷・ログイン状態・時間帯で変動し得る。
> 数値は目安として扱い、本番ではタイムアウトとリトライで吸収すること。
