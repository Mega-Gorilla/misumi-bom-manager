# ステップ3c 実同期 PoC — 実測セッション手順書（runbook）

Issue #23 の試験仕様を実行に落とした手順書。**端点A**（ハーネスを動かす PC）と**端点B**（2台目 PC・
同一 Google アカウント・Drive for desktop ミラーモード）で行う。端点B にハーネスは不要 —
Excel でセルを1つ編集して保存する、同期を一時停止／再開する、の2種類の操作だけを行う。

**大原則**

- Drive への書き込みは `__mbm_sync_poc_<run-id>/` 配下のみ。**他のフォルダ・ファイルには一切触れない**
- **各ステップの前に、直前の操作の同期完了を確認する**（判定はハーネスの指紋・マーカー。トレイ表示は補助）
- タイムアウト規定: 同期待ち最大 **5分**（`watch-stable` 300s）／**10秒**同一なら収束。
  超過は **INCONCLUSIVE**（NO-GO ではない）→ Drive・ネットワーク障害なら再試験
- 判定に使う版マーカー: **B0** = D2=800・G2="B0" ／ **A1** = D2=1234（アプリ書き込み）／
  **R1** = G2="R1"（端点Bで手入力）

## 0. 事前準備（両端点）

1. 両PCの **Drive for desktop バージョン**と **Excel バージョン**を記録（結果に併記）
2. 両PCで **Office リアルタイムプレゼンスを OFF**
   （Drive 設定 → 「Microsoft Office のリアルタイム プレゼンス」）。ケース91・92 のときだけ ON に戻す
3. 端点Bで Drive のミラー先フォルダの場所を確認（テストフォルダが同期されてくる場所）
4. 端点A:

```powershell
cd tools/excel-link-poc
pwsh -File gen-syncpoc.ps1              # テンプレート生成（初回のみ）
pwsh -File run-sync-poc.ps1 -Init       # Drive ミラー実体に __mbm_sync_poc_<run-id>/ を作成
```

5. **同期完了を待つ**: 端点Bに `__mbm_sync_poc_<run-id>/`（11ケースフォルダ）が現れること
6. Drive Web で `case-01-normal/bom.xlsx` と `case-08-backup-sync/bom.xlsx` に**共有リンクを作成**し、
   URL（＝ファイル ID）を控える（後で置換前後の同一性を比較する）

## 1. ケース別手順

各ケースの `[A]` は端点Aのコマンド、`[B]` は端点Bの手作業。**ステップ間が barrier**（次の操作を
するまでハーネスは進まない）。結果はケースフォルダの `log.jsonl` に自動記録される。

### case-01 通常同期（合否）

1. `[A]` `run-sync-poc.ps1 -Case 01 -Step 1` — アプリ書き込みフロー一式（F0→temp→最終照合→置換）
2. `[B]` bom.xlsx を開いて **D2=1234 になっている**ことを確認して閉じる（保存しない）
3. `[A]` `-Case 01 -Step 2` — ローカルの A1 生存を機械確認
4. 記録: Drive Web でファイル ID・共有リンクが**置換前と同じ**か／バージョン履歴に何が残ったか

### case-02 リモート更新が先（合否）

1. `[A]` `-Case 02 -Step 1` — F0 記録のみ
2. `[B]` bom.xlsx の **G2 に `R1` と入力して保存**、閉じる
3. `[A]` `-Case 02 -Step 2` — R1 到着を `watch-stable` で待ち、指紋変化＝**書き込み拒否**を確認（PASS 条件）

### case-03 読込後・置換前にリモート反映（合否）

1. `[A]` `-Case 03 -Step 1` — F0 記録＋temp 生成で停止（barrier after-read-f0）
2. `[B]` G2 に `R1` と入力して保存
3. `[A]` `-Case 03 -Step 2` — 到着を待ってから置換続行 → **最終指紋照合が競合停止**（PASS 条件）

### case-04 アプリ置換後にリモート更新到着（合否）

1. `[B]` **Drive の同期を一時停止**
2. `[A]` `-Case 04 -Step 1` — A1 へ置換（クラウドには A1 が上がる）
3. `[B]` （停止したまま）G2 に `R1` と入力して保存 → **同期を再開**
4. `[A]` `-Case 04 -Step 2` — どちらが本体になったか・敗者の行き先を記録
5. 記録: **異常がユーザーに明示されたか**（Drive 通知・競合コピー・ファイル名）。
   ユーザー変更（R1）が警告なしに消えたら **NO-GO**

### case-05a / case-05b 同期停止中に双方変更（参考）

1. `[A]`・`[B]` 両方で同期を一時停止
2. `[A]` `-Case 05a -Step 1`（A側の変更）／ `[B]` G2 に `R1` と入力して保存
3. 再開順序: **05a = A が先に再開** → 完了後 B 再開 ／ **05b = B が先に再開** → 完了後 A 再開
4. `[A]` `-Case 05a -Step 2` — 収束時間・生存マーカー・新規ファイルを記録（参考値）

### case-06 オフライン復帰（合否）

1. `[B]` 同期を一時停止（bom.xlsx は **B0 のまま何も編集しない**）
2. `[A]` `-Case 06 -Step 1` — A1 へ置換・同期
3. `[B]` 同期を再開
4. `[A]` `-Case 06 -Step 2` — **古い B0 が A1 を上書きしないこと**（PASS 条件）

### case-07 競合コピー（参考）

1. case-05 と同型の競合を発生させる（両停止→双方変更→再開）
2. `[A]` `-Case 07 -Step 2` ＋ `-Scan` — 新規ファイルをケースフォルダ・PoC ルート・**ミラールート直下**で捜索
3. Drive Web で **My Drive 直下・Lost & Found・バージョン履歴**も確認（`bom (1).xlsx` だけを探さない）。
   競合コピーの**正確なファイル名と場所**を記録

### case-08 backup 同期（合否）

1. `[A]` `-Case 08 -Step 1` — 置換後、`bom.backup.xlsx`（B0）がケースフォルダに残る
2. 観察: backup が端点B・Drive Web に**同期されるか**（されるなら本実装は backup をフォルダ外に置く判断材料）
3. `[A]` `-Case 08 -Step 2` — backup 内容が B0 のままであることを機械確認
4. 記録: 事前に作った共有リンクが**まだ開けるか**・権限が変わっていないか

### case-91 / case-92 プレゼンス ON セット（実運用確認）

1. 両PCで Office リアルタイムプレゼンスを **ON** に戻す
2. case-91 = case-01 と同じ手順（`-Case 91`）／ case-92 = case-04 と同じ手順（`-Case 92`）
3. 「Safe to edit / Wait to edit / New version created」等の表示が出たら**そのまま記録**

## 2. 各ケースで記録するもの（チェックリスト）

- [ ] `log.jsonl`（自動: 時刻・F0・現在指紋・backup 指紋・ターゲット指紋・watch 結果）
- [ ] 生存マーカー（`marker` 出力: D2 / G2）— 端点A・端点B・（可能なら Drive Web からDL した版）の3点
- [ ] 競合コピー・新規ファイル（`-Scan` ＋ Drive Web の My Drive 直下・Lost & Found）
- [ ] バージョン履歴の状態（Drive Web・**履歴にしか残っていない場合はサイレント消失＝NO-GO 証跡**）
- [ ] 同期完了までの時間（`watch-stable` のログ）
- [ ] Drive クライアントの通知・エラー表示（スクリーンショット推奨）
- [ ] ファイル ID・共有リンクの前後比較（case-01/08）

## 3. 後片付け

```powershell
pwsh -File run-sync-poc.ps1 -Cleanup    # sync-guard の5条件検証を通った場合のみ削除
```

Drive Web のゴミ箱・Lost & Found に残骸がないかを最後に確認。`out/syncpoc-session.json` は
実測記録として残す。

## 4. 判定

Issue #23 §4 のとおり: 合否対象 = case-01/02/03/04/06/08。**GO** は全 PASS＋「ユーザー変更の
サイレント消失なし（履歴のみは不可）・ファイル ID／共有リンク／権限維持」。ID が変わってもリンク・
権限が保たれるなら**条件付き GO**（製品仕様に明示）。タイムアウト・障害は **INCONCLUSIVE**（再試験）。
NO-GO なら**クラウド同期フォルダへの書き戻しを無効化**（plan.md §6.2）。
